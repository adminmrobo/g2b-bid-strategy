# 입찰 전략실 (내부용)

나라장터 낙찰 결과를 매일 자동으로 모아 **업종·기간별 가격 전략, 경쟁률, 유찰, 진행 공고 추천, 우리 회사 성적**을 보여 주는 웹앱입니다. 지금까지 수작업으로 하던 낙찰 데이터 정리와 분석을 자동으로 처리합니다.

- 업종 버튼: 전기공사 · 감리 · 소방 · 사용자 지정 · 다른 업종(전기 감리, 정보통신, 기계설비, 건축, 토목, 조경, 공사 전체, 용역 전체). 여러 개를 함께 고를 수 있습니다.
- 기간 버튼: 최근 1개월 · 3개월 · 6개월 · 1년
- 탭:
  - **가격 전략**: 투찰률별 낙찰 확률 곡선, 추천값 3종(확률 최대형·안전형·수익형), 성적표, 투찰금액 계산기
  - **경쟁 분석**: 참가업체 수, 1순위 여유폭, 하한 미달 비율, 낙찰 상위 업체·HHI, 금액대·기관별 경쟁
  - **유찰 분석**: 월별 유찰률, 금액대·기관별 유찰률, 최근 유찰 건
  - **진행 공고**: 개찰 전 공고를 예상 참가업체 수로 매긴 참여 추천 순위
  - **내 회사**: 우리 회사 참여·1순위·하한 미달 내역

## 처음 쓰는 사람을 위한 안내 지도

비밀번호를 넣고 처음 열면 **연구실 안내 지도**가 뜹니다. 박사·조수 하루·초파리 연구원·주판봇이 정거장 8개(업종 → 기간 → 확률 곡선 → 성적표 → 투찰금액 계산 → 경쟁·유찰 → 참여할 공고 → 내 회사)를 맡아 안내하고, 정거장을 누르면 실제 화면에서 그 자리를 비추며 따라하기가 시작됩니다. 위쪽 **사용법** 버튼으로 언제든 다시 열 수 있습니다.

- 안내 문구·순서·캐릭터는 `docs/guide.js` 맨 위의 `STOPS` 목록만 고치면 됩니다.
- 캐릭터 그림은 `docs/img/char/`에 있습니다(캐릭터 팩 `ahnboat_lab_explainer/packs/character` 1.3, 192px). 그림의 저작권은 안상선에게 있습니다.

## 비밀번호 잠금은 어떻게 동작하나

화면에서 비밀번호만 확인하는 방식은 공개 저장소에서 코드를 열면 풀립니다. 그래서 이 앱은 **데이터 자체를 비밀번호로 암호화**합니다.

1. GitHub Actions가 매일 조달청 API에서 받은 자료를 `APP_PASSWORD`로 암호화(AES-256-GCM, PBKDF2 25만 회)해서 `store/`에 커밋합니다.
2. 같은 비밀번호로 앱용 파일 `data.bin`을 만들어 GitHub Pages에 올립니다.
3. 브라우저에서 비밀번호를 넣어야 `data.bin`이 풀립니다. 비밀번호가 틀리면 데이터를 읽을 수 없습니다.

비밀번호와 API 인증키는 **코드에 없고 GitHub Secrets에만** 있습니다. 화면 코드(HTML·JS)는 볼 수 있어도 데이터는 볼 수 없습니다.

## 처음 설정 (한 번만)

1. **Secrets 넣기**: Settings → Secrets and variables → Actions → *New repository secret*
   | 이름 | 값 |
   | --- | --- |
   | `SERVICE_KEY` | 공공데이터포털 일반 인증키 (Encoding·Decoding 아무것이나) |
   | `APP_PASSWORD` | 앱 비밀번호 |
   | `MY_BIZNO` | (선택) 우리 회사 사업자등록번호. 여러 개면 쉼표로 구분 |
2. **Pages 켜기**: Settings → Pages → *Build and deployment* → Source를 **GitHub Actions**로 바꿉니다.
3. **첫 실행**: Actions → *매일 수집·배포* → *Run workflow*.
4. 끝나면 `https://adminmrobo.github.io/g2b-bid-strategy/` 에서 비밀번호를 넣고 엽니다.

## 데이터 적재 일정

- 매일 05:23(한국시간)에 자동으로 실행됩니다.
- 매번 다시 받는 것: 최근 3일 낙찰 결과, 이번 달·지난달 공고.
- 처음에는 지난 400일을 거꾸로 채웁니다. 조달청 API는 **하루 단위로만 조회**되고 **기능별 하루 10,000회** 한도가 있어서, 처음 1년치를 다 받는 데 며칠에서 1~2주가 걸릴 수 있습니다. 남은 작업량은 화면 아래쪽에 표시됩니다.
- 한도에 걸리면 받은 데까지 저장하고, 다음 날 이어서 받습니다.

조정이 필요하면 Settings → Secrets and variables → Actions → *Variables*에 값을 넣습니다.

| 변수 | 기본값 | 의미 |
| --- | --- | --- |
| `API_BUDGET` | 8500 | 한 번 실행할 때 쓸 API 호출 수 |
| `MAX_MINUTES` | 300 | 한 번 실행할 때 수집에 쓸 최대 시간(분) |

> 저장소가 **Private**이면 Actions 무료 사용 시간(Free 플랜 월 2,000분)이 있습니다. 처음 적재 기간에는 `MAX_MINUTES`를 60 정도로 낮추세요. 적재가 끝난 뒤의 일일 실행은 몇 분이면 끝납니다.

## 비밀번호 바꾸기

`store/`가 옛 비밀번호로 암호화되어 있으므로 다시 암호화해야 합니다.

```bash
pip install -r requirements.txt
OLD_PASSWORD=옛비번 APP_PASSWORD=새비번 python -m collector.run rekey
git add store && git commit -m "rekey" && git push
```

그다음 Secrets의 `APP_PASSWORD`를 새 비밀번호로 바꾸고 워크플로를 한 번 실행합니다.

## 분석 방법 요약

- 입찰 1건마다 **하한선(기초금액 대비) = 낙찰하한율 × 사정률(예정가격 ÷ 기초금액)** 을 계산합니다. 투찰률 x가 `하한선 ≤ x < 1순위 투찰률` 이면 1순위가 되었을 입찰로 셉니다.
- 이 기준으로 과거 입찰 전체에서 투찰률별 낙찰 확률 곡선을 그립니다(±0.05%p 평활).
- **성적표**: 기간의 앞 70%로 고른 투찰률을 뒤 30%에 적용해 실제 적중률과 무작위 기준선(평균 1/참가업체 수)을 비교합니다. 기준선보다 낫다는 근거가 없으면 화면에 그렇게 표시합니다.
- **계산기**: 복수예가 15개 중 4개 평균 추첨을 2만 번 시뮬레이션해 하한 미달 위험을 계산합니다.
- **진행 공고**: 같은 기관·금액대, 없으면 같은 금액대, 그것도 없으면 같은 업종의 과거 입찰에서 참가업체 수를 가져와 기대 낙찰 확률을 계산합니다.

확률은 과거 자료로 추정한 값이며 낙찰을 보장하지 않습니다. 이 앱은 투찰을 대신하지 않습니다.

## 화면만 바꾸기 (예: 연구실 콘셉트)

계산은 `docs/analysis.js`, 화면은 `docs/app.js`와 `docs/index.html`이 맡습니다. 화면을 새로 꾸밀 때는 이 두 파일만 바꾸고, `analysis.js`·`collector/`·`store/`·워크플로는 그대로 둡니다. 데이터 수집과 비밀번호 잠금은 계속 동작합니다.

`analysis.js`가 주는 함수(전역 `G2B`):

| 함수 | 돌려주는 것 |
| --- | --- |
| `G2B.prepare(data)` | 복호화한 데이터를 입찰·진행공고 객체 목록으로 |
| `G2B.categoryFilter(keys, custom)` · `G2B.periodRange(last, months)` | 업종·기간 필터 |
| `G2B.strategy(bids, {floor, cost})` | 확률 곡선, 추천 3종(best·safe·profit), 성적표(score), 하한선 통계 |
| `G2B.calc({bss, fl, span, x}, bids)` | 투찰금액, 하한 미달 위험, 하한가 범위 |
| `G2B.compete(bids)` | 참가업체 수·기준선·HHI·월별·금액대별·상위 업체·기관별 |
| `G2B.fail(bids)` | 유찰률·재공고·월별·금액대별·기관별·최근 유찰 |
| `G2B.upcoming(bids, notices, today)` | 진행 공고 참여 추천 순위 |
| `G2B.mine(bids)` | 우리 회사 참여·1순위·하한 미달·아깝게 놓침 |

## 수집 진행 상황 보기

Actions → 실행 기록 → collect → *수집 (이어받기)* 에서 하루치가 큰 날은 25페이지마다 `… 75/188 페이지` 처럼 진행 줄이 나옵니다. 실행 마지막 줄의 `남은 예상 호출 … → 약 N일`이 1년치 적재가 끝날 때까지 남은 날수이며, 같은 내용이 앱 화면 아래쪽에도 표시됩니다.

개인정보(대표자명·담당자명·연락처)는 저장하지 않습니다. 업체는 상호와 사업자번호만 남깁니다.
